# H3 Portrait 1.5.3 build hotfix

Both GitHub Actions logs uploaded on 2026-10-06 failed at the same Docker stage.
The production Draft/Generate gate correctly checks Ollama residency before H3,
but two regression tests patched a different imported copy of local_runtime.
During Docker build there is no Ollama daemon on port 11434, so those tests made
real loopback calls and failed with connection refused.

## Changed files

- `h3_portrait/node/reference_video.py`
  - adds a late-bound `_require_ollama_idle()` wrapper so residency checks remain
    runtime-safe and can be mocked reliably in build tests and hot reloads.
- `h3_portrait/node/local_runtime.py`
  - converts loopback connection failures into a clear H3/Ollama readiness error
    instead of leaking a raw `requests.ConnectionError` traceback.
- `h3_portrait/tests/test_release153.py`
  - patches the exact DraftGate runtime hook instead of a duplicate module import.

No model weights, quality settings, workflow graphs, KREA loader protections,
H3 loader protections, Ollama model choices, or Full/Lite profiles were changed.

## Apply

Overlay the hotfix ZIP at the repository root and replace matching files. Then
commit and rerun both H3 Portrait Full and Lite GitHub Actions. The earlier
failed runs did not reach successful image publication, so the existing 1.5.3
tags can be reused.
