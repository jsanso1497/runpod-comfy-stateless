# H3 Portrait 1.5.3: startup, memory handoff and model-family fixes

Based on the supplied H3 Portrait 1.5.2 full source package. This is a source
update, not a prebuilt Docker image and not a live GPU validation.

## What changed

- ComfyUI waits until both required Full prompt models are installed and their
  capabilities are checked. Lite checks its single 8B Instruct model. Port 8888
  remains available during startup; port 8188 does not open prematurely.
- Ollama model pulls show progress in the main startup log. Installed models are
  reused. Failed/stalled transfers are retried into the same model cache, with
  three attempts inside one total time budget per model. No partial-file cleanup
  or automatic downgrade to 8B is performed.
- A missing model is caught before Reference Pack prepares an expensive prompt.
  An empty `ollama list` during a download is not interpreted as proof that the
  download never started. Inspect the explicit status file instead.
- The actual Reference Pack call frees ComfyUI's loaded models before local VLM
  inference, explicitly unloads the selected Ollama model in a finally block,
  and verifies that `/api/ps` is empty before returning. The Generate gate also
  rechecks residency when a previously generated prompt is cached.
- H3 startup defaults to `--disable-dynamic-vram --reserve-vram 4.0`. This avoids
  the dynamic allocator involved in the reported `VRAM grow failed` exception.
  It does not guarantee that arbitrarily large jobs fit in GPU memory.
- Protected loaders have separate KREA, H3 video and H3 audio choices. Selecting
  the H3 encoder in KREA, or Qwen's image VAE in the H3 audio slot, is rejected
  before loading weights. Stale model-download metadata is removed from these
  installed copies. H3's encoder type is explicitly `minimax`; KREA's is `krea2`.
- New versioned workflows are installed alongside old saved workflows. Existing
  user edits, prompts, references, LoRAs and output files are not overwritten.

Full remains 32B Instruct + 32B Thinking for local prompt roles, BF16 H3 generation,
25-step High fidelity and maximum reference image sizing. Lite retains its own
INT8/8B profile. Existing KREA/SeedVR2 and H3 Media generation settings are retained.
No CUDA/PyTorch upgrade, new generative upscaler or hosted prompt API is introduced.

## Apply to your repository

Use `H3_Portrait_1.5.3_Update.zip` over the matching 1.5.2 source. Extract it locally
and upload its contents into the repository root, merging directories and replacing
matching files. Do not upload an enclosing folder. Do not delete the repository.
The update ZIP excludes `config/lora_links.txt`, so keep that existing file.

The full source ZIP also omits the private LoRA list. For a fresh repository, restore
your own `config/lora_links.txt`, or create it as an empty text file when no private
LoRAs are needed. The snapshot intentionally requires its presence but never hashes
or reads its contents. Do not replace it with a shared placeholder in an existing repo.

Check these hidden paths survived the browser upload:

```text
.github/workflows/build-h3-portrait.yml
.github/workflows/build-h3-portrait-lite.yml
.github/workflows/build-image.yml
```

Commit to `main`. Run **Build H3 Portrait template** for Full or **Build H3 Portrait
Lite template** for Lite. The separate general image build is not needed for this
H3 template. Do not use the new tag before its corresponding build succeeds.

## RunPod template

Full image:

```text
ghcr.io/jsanso1497/runpod-comfy-stateless:h3-portrait-v1.5.3
```

Lite image:

```text
ghcr.io/jsanso1497/runpod-comfy-stateless:h3-portrait-lite-v1.5.3
```

Keep your existing GHCR credential, HTTP ports `8188,8888`, blank start command,
and adequate disk capacity for the enabled model catalogs. The previous Full
400 GB container-disk setup can be retained. This release does not change storage
persistence or mount a volume automatically.

Full environment, with all three optional features enabled as requested:

```text
OLLAMA_MODEL=huihui_ai/qwen3-vl-abliterated:32b-thinking-q4_K_M
ASSET_DOWNLOAD_WORKERS=2
HF_TOKEN={{ RUNPOD_SECRET_huggingface_token }}
CIVITAI_TOKEN={{ RUNPOD_SECRET_civitai_token }}
FILEBROWSER_PORT=8888
FILEBROWSER_PASSWORD={{ RUNPOD_SECRET_filebrowser_password }}
ENABLE_KREA_IDENTITY=1
KREA_IDENTITY_UPSCALE=1
ENABLE_H3_MEDIA=1
H3_DYNAMIC_VRAM=0
H3_RESERVE_VRAM=4
```

Keep your actual secret names when they differ. No surrounding quotes in the
RunPod value fields. No OpenRouter key is needed. Do not expose port 11434.
The two new memory variables above already have those defaults in the image.

For Lite, change `OLLAMA_MODEL` to the existing 8B Instruct tag. Enabling the separate
H3 Media feature on Lite still uses that feature's BF16 H3 catalog, as in 1.5.2.

### Optional analysis-model override

Full defaults to the 32B Instruct reference writer. A deliberate override is now
available through `OLLAMA_ANALYSIS_MODEL`; it is used consistently for download,
readiness checks and the installed Reference Pack workflow. No override is required.
It must be an installed/downloadable local non-thinking vision model. The Full
Thinking director and native H3 text encoder are separate and remain unchanged.

### Model cache and slow downloads

The default cache remains `/workspace/h3-portrait/ollama-models`. An optional absolute
`OLLAMA_MODELS` path is honored by the supervised daemon. Reusing it avoids a model
pull only when the cache still exists, for example on an intentionally configured
persistent mount. A genuinely stateless replacement Pod still needs model files.
Retry/resume cannot guarantee a faster connection to Ollama's registry.

Save needed inputs, outputs and workflow exports before replacing or terminating
an existing stateless Pod. This ZIP does not update your current Pod or GitHub for you.

## Which workflows to open

For the Hearmeman-style Full workflow:

```text
H3_Reference_Video_Swap_Local_Full_v1_5_3
```

The Lite version has `Lite` in the same position. KREA Identity and H3 Media copies
now end in `_safe_v1_5_3`. Use these new copies, not an old browser tab or saved 1.5.2
graph. Existing images, direction and seed can be transferred through the UI.

Keep the H3 stack separate:

```text
Diffusion: minimax_h3_ref2va_bf16.safetensors
Encoder: qwen3vl_32b_minimax_h3_bf16.safetensors, type=minimax
Video VAE: minimax_h3_video_vae_fp16.safetensors
Audio VAE: minimax_h3_audio_vae_fp32.safetensors
```

KREA Identity uses:

```text
Diffusion: krea2_turbo_bf16.safetensors
Encoder: qwen3vl_4b_bf16.safetensors, type=krea2
Image VAE: qwen_image_vae.safetensors
```

The existing general Raw KREA recipes retain their Raw checkpoint and sampler.
Do not change any of these internal encoders when selecting an Ollama model.

## First live check

Wait for `H3 STARTUP GATE PASSED`, then `H3 PORTRAIT 1.5.3 READY`. Open ComfyUI.
In the new Reference Video workflow use a short clip and run Draft only first.
The startup/download status is available from the terminal:

```bash
cat /workspace/h3-portrait/ollama-status.json
OLLAMA_HOST=127.0.0.1:11434 ollama list
OLLAMA_HOST=127.0.0.1:11434 ollama ps
```

After a successful local draft, the log should include:

```text
H3 GPU HANDOFF VERIFIED: Ollama /api/ps is empty.
```

Review the prompt, then use Generate video. A remaining out-of-memory error needs
the new full error report and requested resolution/reference sizes; it is not
proof that the protected encoder selection is wrong.

## Repair an old saved workflow without discarding its prompt

The repository includes a conservative repair tool for the exact model-family
mixups in the supplied reports. Export a workflow JSON and run from the repo:

```bash
python tools/repair_workflow_models.py old-workflow.json repaired-workflow.json
```

This writes a new file using native loaders, so it can also be imported on an older
Pod that already has the correct model files. Add `--protected` only after installing
1.5.3. Prompts, references, seed, sampler settings and links are preserved. The tool
refuses ambiguous mixed-model graphs and does not guess audio/video roles from titles.
It repairs model selections, not arbitrary custom-node or sampling problems.

Read `VALIDATION_1_5_3.md` for executed tests and the remaining live checks.
