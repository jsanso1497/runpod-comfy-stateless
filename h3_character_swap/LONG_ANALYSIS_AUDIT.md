## Primary developer references consulted

1. Ollama chat API: https://docs.ollama.com/api/chat
   `options`, image-bearing messages, structured JSON/schema output, `keep_alive`,
   completion reason and token-usage fields. These support adjustable budgets,
   recorded actual usage and explicit unloading. They do NOT promise output length.
2. Ollama parameter reference: https://docs.ollama.com/modelfile
   `num_predict` is maximum generated tokens; `num_ctx` is total context capacity.
3. Ollama context guidance: https://docs.ollama.com/context-length
   Larger context increases memory requirements. Inspect placement with `ollama ps`.
   The new analyzer uses bounded per-request limits rather than a large auto default.
4. ComfyUI H3 prompt guidance:
   https://docs.comfy.org/tutorials/video/minimax/minimax-h3-prompt-guide
   Preserve reference labels, distinguish source/reference roles, describe reference
   sheet panels explicitly and keep shot timing within the selected clip.
5. Exact pinned H3 tokenizer implementation:
   https://github.com/Comfy-Org/ComfyUI/blob/79be670e2d9be63e238785af307369d2b9039ed1/comfy/text_encoders/minimax.py
   https://github.com/Comfy-Org/ComfyUI/blob/79be670e2d9be63e238785af307369d2b9039ed1/comfy/text_encoders/qwen3vl.py
   The native encoder combines prompt text and reference vision blocks. The
   permissive tokenizer length is not a VRAM guarantee or a measured quality target.

## Integration decisions, not external benchmark conclusions

Default 16,384 output tokens, 32,768 total context and 16 source samples are chosen
for this request. Up to 32,768 output tokens with 65,536 context is exposed as an
explicit higher-cost option. No comparative test establishes that a longer prompt
or these exact defaults improve Akatz likeness or action adherence.

Two outputs separate the detailed selected-clip timeline from a reusable chain-safe
identity/preservation prompt. This prevents a known logical mismatch: replaying the
first five seconds' text as instructions for every later source section. It is not
a new per-chunk vision model or an automatically verified choreography system.

Legacy BFS code is retained to avoid breaking old saved canvases, but no BFS output
is generated by the new analyzer. No upscaler, dependency upgrade, resolution change,
new weight selection, or FileBrowser deployment is bundled into this focused update.
